🔵 google/cctz · production
Exclude Apple platforms from _XOPEN_SOURCE
✓ MERGED INTO GOOGLE PRODUCTION · C++
Problem (2 lines): macOS + GCC 15 builds failing for all Apple users. _XOPEN_SOURCE lowered __DARWIN_C_LEVEL, hiding C11 symbols (quick_exit) that GCC 15 requires.
Investigation (2 lines): Traced the preprocessor chain to identify __APPLE__ needed the same exclusion as FreeBSD/OpenBSD. Maintainer confirmed.
Solution (2 lines): Added !defined(__APPLE__) to the exclusion list. Verified on real macOS + GCC 15 CI.
Merged by Google engineer
Impact: Unblocked builds for all macOS + GCC 15 users across Google's internal and external CI.

Case Study

Redis clone: benchmarked against reality.

Systems · C++17 · Distributed
KV Store

Production-grade key-value store built from scratch. Started single-threaded, profiled the bottleneck, re-architected to thread-per-connection with mutex-protected shared state.

Performance insight: The 11% gap vs Redis isn't C++ — it's TCP connection reuse. My benchmark opens a new connection per request; Redis clients reuse them. That's where the time goes.

O(1) GET/SET/DEL via doubly-linked list + hash map LRU eviction, with AOF persistence for crash-safety.
